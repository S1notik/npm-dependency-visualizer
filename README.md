# npm-dependency-visualizer

Учебное Java CLI-приложение для варианта 20. Этап 2 получает метаданные
npm-пакета из указанного реестра и выводит объявления его прямых зависимостей.
Рекурсивное построение графа и визуализация относятся к следующим этапам.

## Требования и сборка

Нужны JDK 17 или новее и Maven 3. При первой сборке Maven загружает плагины
и библиотеки; для запроса к реестру также нужен доступ к его серверу.

```sh
mvn clean verify
./run.sh
./run.sh config/example.csv
```

`run.sh` собирает проект и запускает приложение. Без аргумента используется
`config/example.csv`. Единственный аргумент - путь к CSV-конфигурации.
При запуске через скрипт относительные пути считаются от корня проекта;
при прямом запуске `Main` - от рабочей папки процесса.

Для чтения CSV используется Apache Commons CSV, для тестов - JUnit. HTTP-запрос
выполняется стандартным `java.net.http.HttpClient`, JSON разбирается кодом
проекта. Менеджер пакетов npm и сторонние библиотеки получения зависимостей
в работе приложения не используются. Maven собирает сам Java-проект.

## Конфигурация

Файл должен быть в UTF-8 и содержать ровно одну запись:

```csv
packageName,repository,testMode,asciiTree
is-odd,https://registry.npmjs.org,false,true
```

- `packageName` - непустое имя без пробелов, например `is-odd` или
  `@babel/core`. Полная проверка правил npm-имён не выполняется.
- `repository` - базовый HTTP/HTTPS URL npm-реестра с хостом без query и
  fragment при `testMode=false`. Путь в базовом URL сохраняется.
- `testMode` - строго `true` или `false`. Тестовый репозиторий из файла
  предусмотрен заданием для этапа 3 и на этапе 2 ещё не реализован. При `true`
  проверяется доступность файла, затем выводится соответствующее сообщение.
- `asciiTree` - строго `true` или `false`. Параметр сохранён из этапа 1;
  вывод дерева относится к этапу 5 и на этапе 2 не выполняется.

Заголовки обязательны, регистр важен, порядок столбцов свободный.
Пустые строки игнорируются, пробелы по краям значений удаляются. Поддерживаются
кавычки, запятые и переносы строк внутри кавычек по правилам CSV; кавычка
внутри поля записывается как `""`.

## Получение зависимостей

1. Программа читает и проверяет конфигурацию.
2. К URL реестра добавляется имя пакета и `/latest`, например
   `https://registry.npmjs.org/is-odd/latest`. Для имён вида `@scope/name`
   специальные символы кодируются в URL. Если базовый адрес содержит путь,
   он сохраняется.
3. Реестр возвращает JSON-манифест версии, обозначенной тегом `latest`.
   Программа проверяет JSON, имя и версию и читает группы зависимостей.
4. Непустые группы выводятся отдельно; имена внутри группы сортируются.

Выводятся все объявления из `dependencies`, `optionalDependencies`,
`peerDependencies` и `devDependencies` с сохранением их групп и строк версий.
Это разные виды связей: необязательные зависимости могут не установиться,
peer-зависимости описывают совместимость с окружением, а dev-зависимости
относятся к разработке пакета. Совпадающее имя остаётся в каждой группе, где
оно объявлено; в правилах npm `optionalDependencies` переопределяет запись
из `dependencies` с тем же именем. Вывод - содержимое манифеста, а не точный
список того, что npm установит в конкретном окружении.

Пример формата вывода для условного манифеста:

```text
Пакет: demo@1.2.0 (тег latest)
Прямые зависимости из манифеста:
dependencies:
  alpha = ^2.0.0
optionalDependencies:
  beta = ~1.0.0
```

Если все группы пусты или отсутствуют, выводится `Прямые зависимости не
указаны.`. Значения вида `^2.0.0`, `*`, `npm:...` и ссылки выводятся как
записано в манифесте: фактические версии зависимостей не разрешаются и
зависимости зависимостей не запрашиваются.

На этом этапе выбирается тег `latest`; это не обязательно версия с самым
большим номером. Параметр выбора версии в варианте 20 не предусмотрен.
Публичный реестр не требует авторизации; работа с приватными пакетами и
настройка токенов в этом этапе не реализованы.

## Ошибки и тесты

```sh
mvn test
./run.sh config/missing.csv
```

Ошибки конфигурации, чтения CSV, соединения, HTTP и повреждённого манифеста
выводятся в stderr с кодом завершения 1; успешное выполнение возвращает 0.
Для демонстрации можно указать неизвестный пакет, недоступный адрес реестра,
неверный CSV или `testMode=true` с существующим файлом.

Тесты проверяют конфигурацию первого этапа, формирование URL для scoped-пакетов,
группы и строки версий, пустые зависимости, разбор JSON, ошибки HTTP и сети,
неверный манифест и коды завершения. Транспорт реестра в автоматических тестах
заменяется локальной заглушкой, поэтому сеть им не нужна.

## Структура

- `src/main/java/dev/npmvisualizer/Main.java` - запуск и формат вывода.
- `config/` в Java-пакете - настройки и чтение CSV.
- `registry/` в Java-пакете - HTTP-транспорт, запрос, разбор манифеста.
- `json/JsonParser.java` в Java-пакете - проверка синтаксиса JSON.
- `config/example.csv` - пример конфигурации.
- `tests/` - автоматические тесты; `run.sh` - сборка и запуск.

Описание формата реестра: [npm Registry API](https://github.com/npm/registry/blob/main/docs/REGISTRY-API.md)
и [поля package.json](https://docs.npmjs.com/cli/configuring-npm/package-json/).
