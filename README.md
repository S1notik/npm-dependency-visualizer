# npm-dependency-visualizer

Учебное Java CLI-приложение для варианта 20. Этап 3 строит ориентированный
граф прямых и транзитивных зависимостей npm-пакета. Для обхода используется
DFS без рекурсии; циклы не приводят к бесконечному обходу.

## Сборка и запуск

Нужны JDK 17 или новее и Maven 3. При первой сборке Maven загружает плагины
и зависимости самого Java-проекта. Для работы с публичным npm-реестром также
нужно сетевое соединение.

```sh
mvn clean verify
./run.sh
./run.sh config/example.csv
```

Без аргумента используется `config/example.csv`. Единственный аргумент - путь
к CSV-конфигурации. При запуске через `run.sh` относительные пути считаются
от корня проекта; при прямом запуске `Main` - от рабочей папки процесса.

Приложение не запускает npm и не использует сторонние библиотеки для получения
зависимостей. HTTP предоставляет `java.net.http.HttpClient`, JSON и выбор
поддерживаемых диапазонов SemVer реализованы в проекте. Apache Commons CSV
используется для чтения конфигурации, JUnit - для тестов.

## Конфигурация

Файл в UTF-8 содержит заголовок и одну запись:

```csv
packageName,repository,testMode,asciiTree
is-odd,https://registry.npmjs.org,false,true
```

- `packageName` - имя начального пакета, например `is-odd` или `@babel/core`.
  В тестовом режиме используются только имена из больших латинских букв.
- `repository` - базовый HTTP/HTTPS URL реестра без query и fragment при
  `testMode=false`; путь к существующему файлу тестового графа при `true`.
  Путь, входящий в базовый URL реестра, сохраняется.
- `testMode` - строго `true` или `false`; выбирает файловый или npm-источник.
- `asciiTree` - строго `true` или `false`. Параметр сохраняется, но вывод
  ASCII-дерева относится к этапу 5 и пока не выполняется.

Заголовки обязательны и чувствительны к регистру; порядок столбцов свободный.
Пустые строки игнорируются, пробелы по краям значений удаляются. Поддерживаются
кавычки, запятые и переносы строк внутри кавычек по правилам CSV.

## Тестовый репозиторий

Репозиторий - текстовый файл UTF-8, по одному пакету на строку:

```text
# A зависит от B и C; B и C зависят от D
A: B, C
B: D
C: D
D:
```

Имена состоят из одной или нескольких больших латинских букв. После двоеточия
зависимости перечисляются через запятую; пустой список означает отсутствие
зависимостей. Пустые строки и строки, начинающиеся с `#`, игнорируются.
Каждый упомянутый пакет должен иметь свою строку; повторные определения,
повторные связи и неизвестные имена считаются ошибкой.

Готовые примеры для демонстрации:

```sh
./run.sh config/test-chain.csv
./run.sh config/test-diamond.csv
./run.sh config/test-cycle.csv
```

`chain` - цепочка A → B → C; `diamond` - две ветви с общей зависимостью D
и недостижимым из A пакетом E; `cycle` - A → B → C → A. Вывод для цикла:

```text
Пакеты (4):
  A
  B
  C
  D
Связи (4):
  A -> B
  B -> C
  C -> A (цикл)
  A -> D
Обратные рёбра DFS (признаки циклов): 1
```

## Как строится граф

`GraphBuilder` кладёт корневой пакет в явный стек. На вершине стека хранится
текущий пакет и номер следующей зависимости. Для каждой зависимости программа
добавляет ребро и, если узел ещё не посещён, кладёт его в стек. После обработки
всех зависимостей узел снимается со стека. Алгоритм обхода не использует
рекурсивные вызовы.

Если ребро указывает на пакет, уже находящийся в текущем пути DFS, оно
помечается как обратное: это признак цикла. Ребро к ранее полностью
обработанному пакету сохраняется, но циклом не считается. Выводимое количество
обратных рёбер не является количеством всех возможных простых циклов.
В граф включаются только узлы, достижимые от выбранного пакета.

Для npm корень выбирается по тегу `latest`. Для каждой следующей зависимости
реестр предоставляет список версий, после чего выбирается наибольшая версия,
удовлетворяющая её ограничению. Поддерживаются точные версии, диапазоны с
`<`, `<=`, `>`, `>=`, `^`, `~`, `~>`, wildcard и частичные версии, `||`,
диапазоны через ` - `, prerelease, теги реестра и алиасы вида `npm:...`.
Документ версий каждого пакета кэшируется на время одного запуска.

Узел npm-графа обозначается `имя@версия`: две разные версии одного пакета -
разные узлы. Строки требований сохраняются на рёбрах. В граф входят
`dependencies` и `optionalDependencies`; при одинаковом имени необязательная
запись переопределяет обычную. `devDependencies` и `peerDependencies`
не добавляются как обычные транзитивные рёбра.

Это граф объявленных зависимостей и выбранных совместимых версий, а не точная
копия дерева установки npm: здесь не моделируются peer-конфликты, hoisting,
lock-файлы, overrides, ограничения платформы и другие правила установки.
Git-, URL-, file- и workspace-спецификации зависимостей пока не разрешаются:
программа сообщает об ошибке, а не подставляет произвольную версию. Ошибка
при загрузке необязательного пакета также прерывает построение графа.

## Ошибки и тесты

```sh
mvn test
./run.sh config/missing.csv
```

Ошибки CSV, отсутствующих вершин, HTTP, JSON и разрешения версий выводятся
в stderr; код завершения - 1. Успешное построение возвращает 0. Частичный граф
при ошибке не печатается.

Автотесты проверяют конфигурацию, HTTP-логику с заглушкой, SemVer, тестовый
репозиторий, транзитивные связи, общие узлы, циклы, несколько версий пакета
и путь длиной 20 000 узлов без рекурсии. Тестам не нужен доступ к сети.

## Структура

- `Main.java` - запуск, выбор репозитория, вывод графа и ошибок.
- `config/` в Java-пакете - настройки и чтение CSV.
- `graph/` в Java-пакете - итеративный DFS, граф и файловый репозиторий.
- `registry/` в Java-пакете - HTTP, npm-манифесты и кэш версий.
- `semver/` в Java-пакете - разбор и проверка ограничений версий.
- `json/` в Java-пакете - собственный JSON-разборщик.
- `config/repositories/` и `config/test-*.csv` - демонстрационные сценарии.
- `tests/` - автоматические тесты; `run.sh` - сборка и запуск.

Формат реестра: [npm Registry API](https://github.com/npm/registry/blob/main/docs/REGISTRY-API.md).
Правила версий: [npm SemVer](https://docs.npmjs.com/cli/v6/using-npm/semver/).
